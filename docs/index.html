Heads-up (Aug 2026): auto mode is now the default for new Pro, Max, and Team Claude Code sessions, so check the mode indicator before you start. Auto is best-effort, not a safety boundary: the more the tool does on its own, the more changes you have to read. Modes do not exist at Level 1 (no file access), and no mode replaces the verify step.
How the pieces fit

Capture, draft, verify.

The bench is a bad place to type. However the words get in, the agent turns them into a clean entry and you check it. Three steps, and the last one is yours.

1

🎤 Capture

Speak or scribble the note while your hands are busy. Dictation turns talk into rough text you never had to type.

Built-in dictation (Windows Voice Typing, macOS & iOS Dictation, the Gboard mic), a voice-memo app, or a transcription service.
2

🤖 Draft

The agent expands shorthand, fixes the format, and flags what is missing, without inventing values. That is the prompt below.

3

✅ Verify

Capture and draft both mishear things, numbers and units most of all. You read it against what you saw, and then it is yours.

The verify step, in practice

How to catch its mistakes.

The rule is "you are the record of truth." This is how you actually do the checking, no coding required. Run the whole list when the output will touch a figure, an order, a database query, or a manuscript.

  • Quote before claim.Tell it: before you state any value, paste the exact source row it came from. The receipt should sit next to the claim.
  • Cross-check against the file.Open the real file and confirm counts, sample IDs, and accession numbers. An ID that is off by one character is still wrong.
  • Watch the confident-but-vague words."Appears to", "should be", "consistent with", "roughly" are the spots to demand a specific source or number.
  • Check the citations.Make it give the exact supporting quote, then confirm the paper and the quote are real. Fabricated references are a known failure.
  • Restart and run all.For any notebook it edited, rerun from a clean slate to catch stale leftover state.
  • Ask it to critique itself."Find the weakest step in your own answer" often surfaces the shaky assumption. Helps, but is not a guarantee.
  • Diff against a known-good value.Compare new output to a control, a prior result, or a total you counted by hand.
  • Sanity-check units and orders of magnitude.Does the concentration, p-value, read count, or fold-change land in a physically plausible range?

The biggest trap is fluent confidence. Clean prose is not evidence, and the tool will happily apologize and then repeat the same error.

Level 1 · try it in 2 minutes

The notebook-entry prompt.

Copy this. Paste it into Claude or ChatGPT. Add one real bench note where it says so. The magic is point 3: it makes gaps stay gaps instead of getting invented.

notebook-entry-prompt.txt 
You are helping me turn a rough bench note into a clean lab-notebook entry.

Do three things:
1. Rewrite my shorthand into clear, full sentences, using a consistent structured
   format with these fields: Date, Experiment, Plant material / sample, Treatment,
   Measurement, Result, Notes. Mark a field "[not recorded]" if my note lacks it.
2. List separately, under "Missing or unclear," any field a reader would need but
   cannot find, and any place my note is ambiguous.
3. Do not invent, guess, or fill in any value I did not write. If a number, unit,
   date, or ID is missing, say it is missing. Do not assume standard values.

Keep my original meaning. Do not add interpretation I did not state.

Here is my bench note:
---
[PASTE YOUR NOTE HERE]
---

What you get back

A clean, fielded entry — plus a "Missing or unclear" list that names what you forgot to write down (pot volume, units, the scoring key) instead of quietly making it up.

Then you

Read every field against what you actually did. Fix anything wrong. Retype the final version into your real notebook. That step is the point.

Chat context pack

No file access? Paste this small summary at the start of each chat. Copy it below.

chat-context-pack.txt 
Project context (read before answering):
- Project: [one line: what this project is]
- I am: [your role, e.g. wet-lab, recording phenotype data]
- Canonical files (the real, trusted ones): [name them, e.g. samples_master_v3.csv]
- Current state / where we left off: [one or two sentences]
- Rules that matter here:
  1. Do not invent numbers, IDs, dates, or units. If something is missing, say so.
  2. Report [group A] and [group B] separately; do not combine them.
  3. [any other rule that has bitten you before]

Wider than you'd guess

Things you can do that you might not picture.

Beyond cleaning up notes, these tools are surprisingly good at small, one-off jobs that used to mean asking someone or giving up. You still verify the output.

🧾

Turn a folder of messy notes into one consistent, searchable record.

📄

Draft a methods paragraph from your logs, with every number left for you to check.

🔤

Reshape a spreadsheet for a repository upload: rename columns, fix units, split a field.

📈

Make a quick chart from a CSV without writing any code.

🖼️

Pull a table out of a photographed page or a PDF into something you can edit.

🔎

Triage a stack of papers: summarize and compare, then spot-check the citations.

✅

Turn a protocol into a printable checklist, and flag where two versions disagree.

🧮

Sanity-check a calculation or a unit conversion before it goes in the paper.

🧱
Where to stop. These shine on small, personal, throwaway tasks. They are not a replacement for maintained software or your institution's systems (your electronic lab notebook, a LIMS, real accounting). If something has to be reliable, shared, and long-lived, don't build a homemade app you will then have to maintain and debug: use a proper tool or ask for help. The point is to remove friction from the work you already do, not to become a one-person software team.
What it costs

Less than you probably think.

Three ways to pay, from nothing to pay-as-you-go. Most lab-notes work never leaves the first two.

Free

$0
free tier of Claude or ChatGPT
  • Everything at Level 1 works here
  • Enough to try this whole guide
  • Daily usage limits, no file access

A subscription

~$20 / month
Claude Pro, ChatGPT Plus
  • Predictable flat fee, higher limits
  • Covers most day-to-day use, including light agentic work
  • Power-user tiers run ~$100–200/mo

Pay-as-you-go

by usage
the API, billed per token
  • A token is a chunk of text, very roughly a word
  • Current models run about $1–$5 per million input tokens; output a few times more
  • Agentic tools (Claude Code) can bill this way or run on your subscription

Check your institution first. Many universities already provide Claude or ChatGPT access. Ask IT or the library before paying out of pocket.

Weigh it against your time. A $20/month tool that saves an hour a week pays for itself many times over. But for lab notes you rarely need more than the free or subscription tier.

Figures as of August 2026 and change often; check the providers' pricing pages for current numbers.

Plain words

The jargon, one sentence each.

Agentic tool
Can take actions for you — read files, run a check — not just chat back.
Prompt
The message you send it, instructions plus any text you paste in.
Dictation (speech-to-text)
Turns spoken words into text, handy at the bench. It mishears too, so verify.
Hallucination
When it states a made-up detail with full confidence. The reason you always verify.
Context window
How much text it can hold in mind at once. Paste too much and older parts fall out.
Token
The chunk of text these tools read and are billed in, very roughly a word. Usage limits and API prices are counted in tokens.
Canonical file
The one real, trusted version everything else should agree with.
Record of truth
You and your raw data. The assistant helps write the record; it does not get to be it.
