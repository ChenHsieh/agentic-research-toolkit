Recipes: a pattern library for the bench

A small set of repeatable moves you will reuse for everyday lab paperwork and data chores. Reach for one when a task is repetitive, mechanical, and low-stakes to draft but still checkable. Every recipe ends with a check, because you stay the record of truth.

Level 1 · plain chat, nothing touches your files start here

  1. Tidy a bench note. Use the notebook-entry prompt; it flags what you forgot rather than inventing it.
  2. Turn a protocol into a stepwise checklist you can print and tick off.
  3. Compare a stack of papers. Paste the actual PDFs so it quotes the sources instead of inventing citations.
  4. Draft a methods paragraph from your notes. Re-check every number against the original log.

Level 2 · agentic tool with read access to a copy of the files learn when needed

  1. Reshape a table for a repository upload: rename columns, fix units, split a field. Spot-check cell by cell.
  2. Make a quick figure or small dashboard. A convenience, not a validated instrument; do not let it be the only place a result lives.
  3. Catch inconsistencies between two versions of a file.

Level 2–3 · add house-rules and a decision log once you rerun it weekly learn when needed

  1. A one-off script to rename or parse many files. Run it on a copied folder first, and ask for a dry-run preview.
  2. Batch the same lookup across a folder.
🧭

Interface note. Use Claude Code or Codex for "do the same thing to every file in this folder." Use Cursor when you would rather watch the changes in an editor. For a genuinely repeated multi-step task, save the working prompt as a skill instead of retyping it.

🧱

Where to stop. Skip a recipe when the job is faster by hand, when the output is load-bearing and you cannot verify it, or when the "recipe" is quietly turning into a permanent app that others depend on. These tools shine on small, personal, throwaway tasks, not on maintained software or your institution's systems.
