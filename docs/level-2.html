The ramp

Level 2 · Give a tool file access learn when needed

The tool can now read your files, and change them if you allow it. This earns its keep when your data has outgrown the chat box: a spreadsheet too big to scroll, or the same lookup repeated across many files.

🗂️

Always point a file tool at a copy, never at your only copy of raw data. Work in a duplicate folder so a mistaken edit can never touch the original. This covers more than experimental data: give it copies of instrument export logs or inventory shelf counts too, not the live files an instrument or order system writes to directly.

When it is worth the setup

  • Reach for it when: you have large or scattered data to search or cross-reference, you do the same lookup repeatedly, or you are folding many files into one curated result.
  • Stay with plain chat when: it is a single day's notes, one experiment, or a paragraph. Bench recording itself rarely needs file access; that comes later, when results get folded into a shared analysis.

Two choices become non-optional

  • Which window you run it in. See Interfaces for the full table. Short version: Claude Code (a terminal) for an agent working across a folder; the VS Code / JetBrains extension if you already work there; Cursor if a helper prefers one editor; Codex to hand off a finished task.
  • Which operating mode it runs in. See Modes. Start in plan mode (reads only, changes nothing), then approve each step once you accept the plan.

The two habits that keep this safe

  1. Ask it to quote the file back to you. "Show me the actual rows" beats "how many are there," because it forces the answer to come from your data, not a guess. If it cannot show you the row, do not trust the number.
  2. Keep approval on. A well-set-up tool proposes a change and waits for your yes. If a tool ever edits your files silently, that is a setup problem, not a normal mode.
⚠️

Everything from Level 1 still applies, and two things sharpen: a wrong claim can now be about your real data, and a tidy summary can hide a partial read (some files may not have opened). Ask "did every file open?" when a number matters, and run the verification checklist.

Ready for a standing setup?

If you rerun the same kind of work often enough that you want it to behave the same way every time, that is Level 3: a house-rules file, a one-page brief, and a decision log.
