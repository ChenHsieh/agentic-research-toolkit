Modes: how much freedom

Once a tool can touch your files, one setting decides whether it changes them while you watch or on its own. Know which mode you are in before you say go.

SituationModeWhat it does
First time on a task, real files, want to see the whole plan firstPlan modeReads only, writes you a plan, changes nothingstart here
Plan accepted, want to watch each edit landApprove each stepPauses before every edit or commandstart here
Low-stakes throwaway work, a folder with no unpublished dataAuto-accept (keep shell approval on)Makes edits itself, pauses for riskier actionslearn when needed
Large repetitive software jobFull-auto / skip permissionsActs unattendedusually overkill
⚠️

Heads-up (Aug 2026): auto mode is now the default for new Pro, Max, and Team Claude Code sessions, so check the mode indicator before you start. verify Auto is best-effort, not a safety boundary: the more the tool does on its own, the more changes you have to read.

How to think about it

  • Plan mode first for most work. It reads and proposes, changes nothing, and lets you catch a bad plan before any file moves.
  • Approve each step once you accept a plan and want to watch each edit land.
  • Auto-accept only for throwaway work in a folder that holds no unpublished data, and keep approval for shell commands on.
  • An allowlist should only ever silence harmless read-only commands, never a command that deletes, moves, or sends.
🛡️

Modes do not exist at Level 1 (no file access), and no mode replaces the verify step. Approving a plan flips you from "just planning" into "actually acting," so read what it switches you into.
