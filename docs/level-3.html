The ramp

Level 3 · The fuller pattern learn when needed

Worth setting up once a project runs long enough that you want the assistant to behave the same way every session. Left to itself it starts each conversation from nothing and guesses; these small files give it a written memory you can see and correct.

3.1 · Instruction files (CLAUDE.md, AGENTS.md)

Write your standing rules down once so you stop retyping them every session: which files are canonical, what it must not edit without asking, how to report numbers.

  • CLAUDE.md if Claude Code is your only tool. As of Aug 2026 it reads CLAUDE.md and does not natively read AGENTS.md. verify
  • AGENTS.md if you switch between tools. It is the shared cross-tool format that Codex, Cursor, Copilot, and Gemini CLI read.
  • Want both? Keep AGENTS.md as the real file and add one line, @AGENTS.md, at the top of CLAUDE.md so Claude Code pulls it in. verify
  • Use a one-page brief instead (just a chat message) when the instructions are for a single task, not standing policy.
⚠️

A rule in the file is a request, not a lock. "Do not edit /raw_data" is a reminder, not a wall, so still verify. Keep it under about 200 lines, and remember a synced folder carries your rules, and everything else in it, up to the cloud.

Grab the fill-in-the-blanks starters on the Templates page.

3.2 · Skills, and when a skill is the wrong tool

A skill (a small folder with a SKILL.md file) packages a repeated, do-it-exactly-this-way task so the assistant applies it the same way each time without you re-explaining. The plain answer for which tool to reach for:

Use…When
A promptA one-off. It vanishes when the chat ends.
An instruction fileContext you want loaded into every session (your project, your writing style).
A skillA set of steps that should load only for one recurring task and stay out of the way otherwise.
A templateYou just need a fill-in-the-blanks document.

Ready-made document skills (Word, PDF, PowerPoint, Excel) at github.com/anthropics/skills work out of the box. Only install skills from sources you trust, keep truly sensitive data out, and see the Resources page for curated libraries.

3.3 · The dated decision log

Keep the reasoning ("chose primer set B because…") in a durable file, not trapped in a chat that will reset. Name files by date so they sort correctly: docs/log/20260314_topic.md.

🗓️

Cloud sync (OneDrive, Dropbox, Drive) changes files' "date modified" when it syncs. So find your newest log by sorting on the date in the filename, not by modified time.

3.4 · Connect your sources

Let the assistant search a live service (Drive, Gmail, PubMed, Zotero) instead of you copy-pasting the same material every session. This is powerful and has real privacy risks, so it gets its own page: Connect your sources.

A word on trust

None of these files make the assistant trustworthy on their own. They make it auditable: every claim traces to a file, every decision has a dated record, and nothing canonical changes without your approval. That is the realistic goal.
