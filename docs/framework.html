A framework

Five layers. The agent does most of the middle one. The other four decide whether the work is any good.

1. Question

Before any compute, write one sentence: what result would change what I believe? If every possible outcome leaves you where you started, the analysis is busywork, however fast it runs.

  • Say what a pure artifact would look like before you see the result.
  • Ask the cheap version first: "how much of this signal is even in the data?" before "does the fancy model use it?"
  • Prefer exploring to confirming. Ask the agent for what you didn't expect.

2. Context

The agent knows nothing about your project except what is written down. Three files do most of the work:

  • CLAUDE.md, the standing rules: where data lives, what never to touch, how to run jobs, how figures should look. Grows by one line per mistake.
  • A brief for each piece of work: goal, inputs, what "done" means, known traps.
  • A status file: what's done, what's open, where outputs are. New sessions start by reading it.

3. Doing

Let it run. Give it the whole task, not one step at a time, and let it write, submit, and check its own jobs. Your time goes to layers 1, 4 and 5.

4. Checking

The step people skip. A result is not a result until something tried to kill it.

  • Make the boring explanation impossible by design, rather than controlling for it afterwards (same composition, same sample size, same depth in both arms).
  • Check that the control actually ran. An empty comparison can look like a pass.
  • Name the unit. Genes in families, samples in batches, cells in animals. If units are grouped, report within groups.
  • Be equally hard on nulls. Was there enough power to see the effect? Would you accept this evidence if it said the opposite?
  • Provenance before assertion. Every number in a sentence comes from a file you can open.

5. Keeping

Chat is not memory. Anything worth keeping goes into git, a status file, or a page someone can open on their phone. Corrections get logged, not quietly overwritten.

Ways of thinking

  • The agent is a fast new student. Capable, eager, and confidently wrong sometimes. Supervise accordingly.
  • Rules beat reminders. If you've said it twice, put it in the rules file. If it matters a lot, turn it into a check that runs.
  • Ship a visible thing early. A rough page that loads beats a polished plan.
  • Reuse before recompute. Check what already exists before asking for a GPU.
  • Size it once. If compute isn't the limit, request what the job needs up front instead of creeping up in five rounds.
  • Plain words. Lead with what exists and what it shows. Put the jargon in parentheses.
